# Часть 3

```sh
python -m part3_parallel.app.performance --path data/input/images --output-dir data/output --readers 3 --processes 2 --variants 3 --repeats 3
```

Поток NN-producer рекурсивно сканирует каталог и помещает пути в ограниченную
queue.Queue. Потоки NN-reader читают изображения и помещают массивы во вторую
ограниченную очередь. Координатор передает их в multiprocessing.Pool через
apply_async с callback и error_callback. Число задач в работе ограничено
семафором; общий счетчик защищен threading.Lock. Результаты сохраняются
в NPY memory map по исходным индексам, независимо от порядка завершения.

Варианты: повороты на 0/90/180/270 градусов, возможное отражение, шум.
Оригинал также сохраняется. Seed задается для каждого индекса и варианта,
поэтому последовательный и параллельный результаты побитово совпадают.

Измеряется весь конвейер, включая создание/остановку процессов и запись
файлов. Порядок двух режимов чередуется; performance_report.json содержит
все замеры, медианы и отношение времен. Кэш ОС не очищается. Ускорение
не гарантировано: на небольшом наборе межпроцессный обмен и запуск
процессов могут занимать больше времени, чем сама аугментация.

GIL в обычном CPython ограничивает параллельное выполнение Python-байткода
потоками. Ожидание I/O и многие операции NumPy/Pillow могут освобождать GIL.
Процессы имеют отдельные интерпретаторы, но требуют сериализации данных.
Выбор режима следует проверять измерениями на нужном объеме данных.

После обработки отправляются сигналы завершения, выполняются task_done,
join потоков, close/join пула. При ошибке очереди дренируются либо подается
сигнал отмены; пул завершается, незавершенный выходной файл удаляется.
