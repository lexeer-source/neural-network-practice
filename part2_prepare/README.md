# Часть 2

Команды из корня:

```sh
python -m part2_prepare.app.cli prepare --path data/input/images --ext png --output data/output/images.npy --size 64
python -m part2_prepare.app.cli prepare --path data/input/tables --ext csv --output data/output/tables.npy --chunk-size 32
python -m part2_prepare.app.cli doctor
```

Приоритет настроек: аргументы CLI, затем NN_* из окружения, затем значения
по умолчанию. Общий `--log-level` задается перед именем команды. Значения
из `.env.example` нужно экспортировать средствами своей оболочки.

Обход рекурсивный и упорядоченный. Изображения приводятся к оттенкам серого,
одинаковому размеру и диапазону [0,1]. CSV должны иметь одинаковые
заголовки и числовые признаки. CSV нормализуются по общим минимумам
и максимумам колонок. Это отдельная утилита подготовки признаков;
разделение train/test и обучение scaler только по train реализованы
в первой части. Целевые метки в команду prepare передавать не нужно.

Запись идет в NPY через memory map; одновременно в памяти находится одно
изображение или блок CSV. CSV читается в два прохода. В памяти остается
список путей (O(числа файлов)), но не весь массив изображений. Manifest JSON
содержит форму, объемы файлов, настройки и реальное время выполнения.

doctor проверяет Python, NumPy, Pillow, Matplotlib, необязательные фреймворки,
CUDA через subprocess.run(nvidia-smi) и текущий каталог. Отсутствие GPU
не считается ошибкой: проект выполняется на CPU.
